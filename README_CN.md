# POV-AI-Storytelling

中文 | [English](README.md)

> 第一视角 AI 视觉叙事方法论：把一个脑洞，逐步做成有因果、有画面衔接的连续视觉故事。

这个项目整理创作中的实际步骤：构思故事、固定设定、安排分镜、生成图片，再对照成图检查和修改。目前提供五份可填写模板，以及《郊区网恋》的 35 镜头案例文档。

它关注一个具体问题：**怎样让一组图片共同讲清一件事？**

可以先[阅读案例](examples/suburban_online_romance/README.md)，也可以从[故事构思模板](templates/story_idea_template.md)开始自己的作品。使用 Markdown 文档即可，不需要安装程序；生成图片时使用你自己的图像工具。

## 适合怎样的创作

项目主要面向连续图文和短篇视觉故事，尤其关注第一视角中的行动、发现和信息顺序。现有案例采用写实手机摄影风格与悬疑结构；模板也可用于日常、情感、冒险、奇幻等故事。

**POV** 是 *Point of View*，即“视角”。在这里，它主要指从故事人物的位置观看世界。观众随着人物接近某个地方、注意某个细节、作出某个选择，从而逐步理解发生的事情。

第一视角不要求每张都有手脚，也不自动意味着主角一直拿着手机拍摄。作品可以使用第三视角、回忆、照片或屏幕，只要视角切换和信息边界清楚。

当前资料以静态图片工作流为主。视频时长、声音和转场可在分镜中补充，完整的视频制作教程仍待完善。

## 快速开始

先做一个范围可控的短故事。模板都提供快速入口，复杂字段按需要补充，无需一次填完全部内容。

| 步骤        | 要解决的问题                           | 使用文件                                              | 得到什么                                        |
| ----------- | -------------------------------------- | ----------------------------------------------------- | ----------------------------------------------- |
| 1. 构思     | 谁想做什么，为什么继续，最后发生什么？ | [故事构思模板](templates/story_idea_template.md)      | `idea.md`：动机、因果与结局方向                 |
| 2. 固定设定 | 哪些人物、地点和道具需要反复保持一致？ | [故事设定模板](templates/story_bible_template.md)     | `story_bible.md`：共用设定与参考依据            |
| 3. 排分镜   | 观众一张一张看到什么，怎样衔接？       | [分镜模板](templates/storyboard_template.md)          | `storyboard.md`：镜头顺序与画面任务             |
| 4. 制作图片 | 这一镜具体怎样生成或修改？             | [单镜头提示词模板](templates/shot_prompt_template.md) | 实际提示词、参考图与输出记录                    |
| 5. 检查修订 | 图片是否做到，前后是否连得上？         | [连续性检查清单](templates/continuity_checklist.md)   | `continuity_notes.md`：偏差、处理决定和复查结果 |

复制模板到自己的作品目录，保留原模板供后续使用。填写后的文件名是建议，可以按项目调整；图片路径和文档引用应与实际文件一致。

完成一组相关镜头后，按展示顺序一起看。检查中发现因果或设计问题，可以回到构思、设定或分镜修改，再同步受影响的图片。流程允许来回调整。

## 创作时抓住这几件事

### 1. 先想清楚人物为什么行动

一句话构思可以从“人物 + 处境 + 变化 + 行动”开始。例如：一个准备考研的学生，在网恋中断后恢复日常生活，却发现通学路上的荒地里出现了一张桌子。

接下来要回答：他为什么注意到它？为什么再次经过？又为什么决定靠近？事件之间有行动和动机相连，故事才不只是奇怪画面的排列。

悬疑故事可以从真相反推它会留下哪些痕迹。其他故事也可以围绕目标、关系或选择展开，不必都有隐藏身份和结尾反转。

### 2. 分开作者设定、画面事实和观众推断

| 层次     | 示例                               |
| -------- | ---------------------------------- |
| 作者设定 | 结尾出现的包，就是开头遗失的那只包 |
| 画面事实 | 两张图都有蓝色方补丁和缺角金属扣   |
| 预期推断 | 观众通过这些特征认出同一只包       |

如果成图中的扣件变了，作者设定仍可保留，但需要记录画面偏差。提示词写了“同一只包”，不等于图片已经呈现了足够的识别依据。

观众理解也需要谨慎判断。没有实际阅读反馈时，记录为预期或检查者判断，不声称所有人都会看懂。

### 3. 让每张图有明确作用

一张图可以推进动作、建立关系、交代环境、承接时间，也可以让情绪停留。不要求每张都出现新线索，但应能说明删掉它会损失什么。

先安排一个主要阅读任务，再放辅助信息。单张静态图只能呈现选定的瞬间；“进入房间、翻开文件、发现照片、回头看人”通常需要拆成多个展示单元。

### 4. 把信息边界写成具体画面

“被子盖住照片主体，只露出右下角”是可以执行的要求。“释放 20% 信息”则无法直接检查。

需要隐藏身份时，说明什么可见、什么被遮挡；需要确认身份时，安排足够清晰的特征。字幕、聊天、配文或旁白也可以承担叙事，只要明确它们在作品中实际出现，而非只写在作者说明里。

### 5. 连续性允许有原因的变化

固定的是对象身份和世界规则，人物可以换装，天气可以变化，物件可以被拿走。变化应符合时间线和行动。

同一地点换机位后，画面左右可能改变；物件位于画外，不等于它消失了。检查时先确认位置与朝向，再判断是否发生错误。

手机随拍是一种风格选择。噪点、模糊和不完美构图不必每张都有，更不能遮掉关键线索。项目也不要求所有故事使用同一种比例或写实风格。

### 6. 修改后检查结果，再记录完成

局部问题优先局部修正，同时写清需要保留的内容。涉及整体空间、姿态或多镜依赖时，再评估重新生成或调整分镜。

比例不符要核对实际宽高，并检查裁切是否会丢失线索；多出元素时，要分清无关新增与原本设计的证据。不要用笼统的“删除所有文字”误删剧情需要的文件或聊天内容。

修改建议、已经生成新图和复查通过是三个不同阶段。记录问题并不意味着问题已经修好。

## 实战案例：郊区网恋

一个考研学生的日常生活、网恋经历与郊区路线，逐渐通过一组视觉线索发生联系。案例按 35 个镜头整理，用来展示构思怎样落到画面，以及实际成图与设定之间有哪些差距。

**下列构思、设定、分镜和检查文档包含完整剧情及结局。** 如果希望先体验故事，从案例入口开始，再阅读拆解。

| 文档                                                         | 内容                             |
| ------------------------------------------------------------ | -------------------------------- |
| [案例入口](examples/suburban_online_romance/README.md)       | 阅读说明、精选图片与文档导航     |
| [故事构思](examples/suburban_online_romance/idea.md)         | 人物动机、因果与故事方向         |
| [故事设定](examples/suburban_online_romance/story_bible.md)  | 人物、地点、道具和作者确定的事实 |
| [完整分镜](examples/suburban_online_romance/storyboard.md)   | 35 镜头的画面与信息顺序          |
| [连续性记录](examples/suburban_online_romance/continuity_notes.md) | 已观察到的偏差、影响和修订事项   |

案例保留了实际制作中的问题，例如界面与时间衔接、道具识别、空间一致性和图片比例。文档中的待修事项不表示图片已经全部修正；它也不是一套完整的原始提示词或视频工程档案。

案例中的异常等级、镜头数量和延迟揭示安排属于这部作品。使用模板时不必照搬，也无需按固定数量安排日常镜头、线索或反转。

## 当前范围与后续计划

目前可使用的内容包括中英文项目入口、五份模板，以及《郊区网恋》的案例文档。人物、地点和道具档案已包含在故事设定模板中，可按需要复制使用。

后续计划逐步补充：

- 面向第一次使用者的完整操作教程。
- 人与 AI 如何讨论、选择方案并记录修改的工作流。
- 带实际参考图和版本记录的提示词示例。
- 更多题材的案例，检验模板在不同故事中的适用性。
- 剪辑、发布和观众反馈的整理方法。

这些是后续方向，尚不代表已经提供对应教程或工具。现有工作流仍需要创作者判断与检查，使用它也不保证作品获得特定传播效果。

## 参与改进

欢迎通过仓库的 Issue 或 Pull Request 提出纠错、模板改进、案例补充和翻译建议。

反馈时尽量指出具体文件、镜头或条目，说明问题与预期改动。涉及连续性时，附上相关图片版本和可见依据，区分设定变更与成图修正。

提交案例或素材时说明来源、署名和使用许可。人物身份、世界规则等作者设定存在疑问时，先明确依据，避免将猜测写成既定事实。
