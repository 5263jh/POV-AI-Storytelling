# Storyboard Template / 分镜模板

> 把故事拆成观众实际看到的画面，明确每一镜的作用、信息与衔接。

先用总表排出顺序，再为难做或重要的镜头补充详细卡片。不必给每张图填满所有栏目。

分镜是制作计划。这里写的“预期理解”和“预期情绪”不代表观众已经理解或产生了这种感受；图片生成后，还需要对照实际画面检查。

## 使用方式

- 输入：故事构思与当前故事设定。若分镜暴露出动机或因果问题，可以回到前两份文件修改。
- 输出：可用于逐镜制作的画面顺序、镜头卡片及必要的衔接说明。
- 填写后保存为作品目录中的 `storyboard.md`。
- 本模板主要面向连续静态图片。用于视频时，可补充时长、动作起止、声音和转场；静态图片不用强填这些字段。
- 本文中的“镜头”指一个展示单元。单张图片只能呈现选定的瞬间；需要表现连续动作时，应拆图、使用明确的多格形式，或改为视频。

## 一、快速版：先把故事排出来

### 项目信息

```text
项目名称：
分镜版本 / 日期：
关联 idea.md / story_bible.md 版本：
展示形式：连续图文 / 视频 / 其他
目标比例：
主要视角：
一句话故事：
观众主要关心什么（目标、关系、问题等）：
结尾回应什么：
当前预计镜头数（可调整）：
```

不要求所有故事都有谜题、异常或反转。按照本作品的行动和变化划分段落，不必套用固定的八阶段结构。

### 镜头总表

| 展示顺序 | 镜头 ID | 时间 / 地点     | 实际画面与选定瞬间 | 本镜作用 / 预期理解 | 与前后镜的衔接           | 制作状态 |
| -------- | ------- | --------------- | ------------------ | ------------------- | ------------------------ | -------- |
| 1        | S001    | ［时间 / 地点］ | ［观众能看到什么］ | ［为何保留］        | ［行动、空间或时间联系］ | 未生成   |
| 2        | S002    | ［时间 / 地点］ | ［观众能看到什么］ | ［为何保留］        | ［行动、空间或时间联系］ | 未生成   |

镜头作用可以是行动推进、人物关系、环境建立、情绪停留、时间过渡或信息揭示。不要求每张都有新线索，但应知道删掉它会损失什么。

### 快速单镜头卡

```text
镜头 ID / 名称：
叙事作用：
时间 / 地点 / 视角归属：
选定瞬间与主要主体：
必须看清的内容：
预期理解及其画面依据：
暂不展示的内容 / 允许露出的局部：
与上一镜的联系：
通往下一镜的行动或时间变化：
必须延续的设定 ID 与当前状态：
必要文字或声音（没有则写无）：
制作状态 / 对应图片：
```

总表足够清楚时，不必再为简单镜头重复填写卡片。

## 二、详细镜头卡：只为需要的镜头展开

### A. 镜头任务与因果

```text
镜头 ID / 名称：
所属段落：
这一镜让行动、关系或理解发生什么变化：
删除后会缺少什么：
主角为什么来到这里或做这个动作：
此前获得了什么信息：
这一行动怎样引出下一镜：
```

“主角发现真相”是叙事任务，不是可直接生成的画面。需要继续说明：看到了什么、哪个细节可辨认、如何与前文建立联系。

### B. 可执行的画面

```text
故事时间 / 时段 / 天气：
地点 ID：
视角归属（谁在看）：
呈现载体（直接场景、照片、手机屏幕、监控等）：
观察位置 / 朝向 / 距离 / 高度：
选定的动作瞬间：
主要主体及其画面位置：
必要的前景 / 中景 / 背景：
光线与关键内容的可读性：
当前镜头需要的比例例外（没有则沿用项目设定）：
```

视角与载体分开填写：第一视角可以看手机，也可以看照片；“手机界面”本身不能说明画面属于谁的视角。

先明确一个主要阅读任务，再安排辅助细节。不把“一图一信息”理解为画面只能容纳一件东西；如果多个信息互相抢夺注意力，或需要不同距离才能看清，再考虑拆镜。

### C. 信息与识别依据

```text
本镜涉及的作者设定（引用 story_bible.md）：
主角在本镜前知道什么 / 误以为什么：
画面直接显示什么：
希望观众据此推断什么：
推断还依赖哪些前文镜头：
可能出现的其他理解：
暂时不能明确展示什么：
允许出现的局部线索：
```

用“能看到红色补丁和断开的扣件”代替“信息可见度 60%”。如果结论需要旁白、标题或聊天文字才能成立，把这部分明确列入作品计划，不要当成画面已经独立说明。

### D. 连续性与制作要求

```text
人物 / 地点 / 道具 ID：
沿用的参考文件及版本：
当前服装、姿态、身体与道具状态：
与上一镜相比发生的变化及原因：
必须保持的空间关系：
本镜不能新增的具体元素及原因：
必须准确呈现的文字 / 界面状态：
需要后期合成或排字的部分：
```

这里只提取本镜所需内容，共用外貌和世界规则在设定文件中维护。禁止项应针对实际风险，例如“本镜背景不出现后续才揭示的人物”，不使用会误删必要线索的笼统限制。

### E. 验收条件与记录入口

```text
本镜通过需要满足的可见条件：
仍待解决的设计问题：
制作状态：未生成 / 待核对 / 需修改 / 已通过
采用的图片文件及版本：
偏差与修订记录链接：
```

“已通过”表示指定图片经过检查，不表示分镜中写下的所有观众反应都得到验证。不要把设计已定、生成完成和检查通过合并成一个 LOCKED 状态。

## 三、按需使用的全局检查表

### A. 因果与转场

| 相邻镜头 / 段落 | 发生的变化                     | 观众如何跟上               | 是否需要补充      |
| --------------- | ------------------------------ | -------------------------- | ----------------- |
| ［前镜 → 后镜］ | ［时间、地点、行动或视角变化］ | ［地标、动作、文字等依据］ | ［无 / 具体内容］ |

跨越时间或省略路程可以成立，关键是观众是否能理解变化。也不必每次换地点都增加全景；只补充真正缺失的定位信息。

### B. 信息、线索与回收

适用于含伏笔、误解、谜题或需要前后识别的故事；没有这些需求时跳过。

| 线索 / 关系 ID | 铺设镜头与可见细节 | 当时可能的理解 | 后续关联镜头 | 计划支持的结论及边界         |
| -------------- | ------------------ | -------------- | ------------ | ---------------------------- |
| ［ID］         | ［细节］           | ［理解］       | ［镜头］     | ［支持什么、尚不能证明什么］ |

作者身份设定、视觉相似和明确证据不是同一回事。比如“同款裙子”可以支持关联，但若要认出同一件衣服，应让独特图案或磨损在相关镜头中可见。

不规定必须铺设三条或五条证据，也不强制最后一张才揭示。证据数量取决于结论是否有足够依据、画面是否读得清楚。

### C. 状态变化与空间衔接

| 镜头范围 | 关联设定 ID            | 本段初始状态 | 发生的变化     | 后续需延续的结果 |
| -------- | ---------------------- | ------------ | -------------- | ---------------- |
| ［范围］ | ［人物 / 道具 / 地点］ | ［状态］     | ［变化与原因］ | ［结果］         |

用于记录换装、持物、开门、移开遮挡、受伤、天气变化等跨镜头事件。稳定外观引用设定文件，不重复抄写整份档案。

动作前后检查时，区分“物件消失了”和“因机位改变到了画外”。相反，换了机位也不能用来掩盖固定布局的无故变化。

### D. 节奏与重复镜头

```text
检查的连续段落：
本段主要任务：
各镜头之间的行动或信息差异：
需要停留的情绪 / 氛围：
相似构图是为了对照、重复感，还是无意重复：
若合并或删除镜头，会损失什么：
保留 / 合并 / 调整的决定与原因：
```

紧张可以升级，也可以缓和；日常镜头可以只建立关系或生活质感。不要为了“每两到四张必须有新信息”添加没有因果作用的异常。

同一机位可以用于对照昼夜或物件变化。需要改变角度时，要有阅读或叙事上的理由，不为避免重复而破坏空间连续性。

如需情绪或异常等级，将其定义为本项目内部的相对标记，并引用统一规则；它们不是观众反应的实测数值。

### E. 结尾

```text
最后一个段落 / 镜头：
直接可见的行动或结果：
回应了前文哪个目标、关系或问题：
依赖哪些前文信息：
刻意保留的未知：
是否存在本应说明却遗漏的因果：
预期留下的感受：
```

结尾可以揭示新信息、确认已有推断，也可以结束一个行动或关系。开放结尾不等于所有问题都不回答。

### F. 视频补充（可选）

```text
镜头 ID：
预计时长：
动作起点与终点：
镜头运动：
对白 / 旁白 / 环境声：
声音来自画内还是画外：
转场方式：
需要停留阅读的文字及时间：
```

时长先作为制作估计，完成剪辑后再实际观看调整；静态图片的展示顺序不等于已经验证的视频节奏。

## 四、填写示例：把抽象任务改成可见瞬间

以下是独立的教学示例，不属于仓库现有作品。

作者设定：主角找到自己遗失的帆布包。包的识别特征是蓝色方补丁和缺了一角的金属扣。

| 顺序 / ID | 实际画面                                                   | 作用与预期理解           | 衔接要求                                     |
| --------- | ---------------------------------------------------------- | ------------------------ | -------------------------------------------- |
| 1 / S001  | 主角第一视角，在长椅上整理包；蓝色补丁和缺角扣件可见       | 建立包的识别特征         | 两个特征都需要足够清楚                       |
| 2 / S002  | 稍后回到同一长椅，原来放包的位置空着                       | 让观众意识到包不在原处   | 固定地标表明是同一长椅；“稍后”可通过配文交代 |
| 3 / S003  | 失物招领处，工作人员把包放到柜台；同样的补丁和扣件朝向主角 | 支持“找回同一只包”的理解 | 地点变化用招领标识或配文交代，必要文字需可读 |

S003 应选定“包已放在柜台上”的瞬间，而不是要求一张静态图同时表现工作人员开柜、取包、递包和主角检查。

这组镜头足以表达遗失和找回；它没有说明谁捡到包。如果故事需要回答这个问题，还要另行设计依据，不能从工作人员持有包直接推断其发现经过。

## 五、编号、制作顺序与版本

### 镜头 ID 与文件映射

| 镜头 ID | 展示顺序 | 当前采用文件     | 制作状态 | 修订记录       |
| ------- | -------- | ---------------- | -------- | -------------- |
| S001    | 1        | ［真实相对路径］ | ［状态］ | ［链接或条目］ |

镜头 ID 用来稳定引用，展示顺序可以调整。插镜时可新增 ID，重排时更新顺序和引用，不必反复改掉所有已有 ID。

新项目可以使用 `shots/shot_001.png`，已有项目沿用真实文件名。不要因为模板示例而把 `.jpg` 写成 `.png`，也不要在文件尚未生成时填成“最终采用文件”。

多个候选版本可以使用 `_v1`、`_v2` 等后缀；最终采用哪一版由映射表明确记录。重命名后同步更新分镜、示例 README 和其他图片链接。

### 制作优先级

```text
需要先验证的高风险镜头与原因：
它们依赖的角色、道具或场景参考：
可在参考稳定后批量制作的镜头：
本批制作范围：
```

优先级由识别难度、文字要求、空间复杂度和依赖关系决定，不把普通生活镜头自动列为低优先级。关键参考尚未固定时，先完成参考，再生成依赖它的镜头。

## 六、进入生成前检查与后续交接

- [ ] 每镜有明确用途，画面描述能够落实为一个展示单元。
- [ ] 主角的关键行动有当时的信息和动机支持。
- [ ] 时间、地点、视角变化有足够的理解依据。
- [ ] 计划让观众得出的重要结论，有可见线索或明确安排的文字、声音支撑。
- [ ] 暂不展示的内容没有误删必要的局部伏笔。
- [ ] 人物、场景与道具引用了当前设定，跨镜状态变化可以衔接。
- [ ] 文字、界面、比例和其他制作难点有具体处理安排。
- [ ] 结尾回应了故事的主要任务，未解决的问题已区分为刻意留白或待补设计。

```text
本次可进入制作的镜头范围：
分镜版本 / 日期：
仍待解决的条目：
```

通过设计检查不代表成图已经通过验收。制作后发现画面不支持原计划时，可以修改图片、调整分镜，必要时回到故事构思；将决定同步到相关文件。

- 用 [shot_prompt_template.md](shot_prompt_template.md) 为当前镜头整理生成要求。
- 用 [continuity_checklist.md](continuity_checklist.md) 核对成图，并把问题记录到作品的 `continuity_notes.md`。
- 共用设定变更回到 [story_bible_template.md](story_bible_template.md) 对应的作品设定文件；故事因果变更回到 [story_idea_template.md](story_idea_template.md) 对应的构思文件。

可参考[《郊区网恋》的分镜](../examples/suburban_online_romance/storyboard.md)。该案例的镜头数量、异常等级和揭示顺序是具体作品的设计，不是通用硬性规则。
