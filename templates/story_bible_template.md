# Story Bible Template / 故事设定模板

> 固定反复出现的人物、地点、道具和世界规则，让后续镜头有共同依据。

先填快速版，再按故事需要补充详细档案。短故事不必填满全部模块；不影响剧情、识别或连续性的细节可以留空。

这份文档记录“故事采用什么设定”。分镜记录“何时展示”，连续性记录记录“成图是否做到”。**写进设定，不等于画面已经实现。**

## 使用方式

- 输入：已完成的故事构思，或至少明确的主角、行动、主要场景与结局方向。
- 输出：一份供分镜和图片制作共同引用的设定文件。
- 填写后保存为具体作品目录中的 `story_bible.md`，保留本文件作为空白模板。
- 已有图片时，先记录其中被作者接受的特征，再列出需要修正的偏差；不要为了迁就错误图片，悄悄改变故事真相。
- “作者内部设定”只是内容标签。公开仓库中的文件仍可被读者查看；需要保留悬念时，应另外安排展示入口。

## 一、快速版：先固定这些

复制下面的内容即可开始。不适用的项目删掉；未决定的内容明确写“待定”，不要让空白变成默认设定。

```text
故事名称：
设定版本 / 更新日期：
当前阶段：构思 / 分镜 / 生成 / 修订
对应构思文件：

1. 世界与视觉
发生的时代、地区与现实程度：
影响剧情的世界规则及限制：
画面风格：
目标比例与交付形式：

2. 视角
主要视角属于谁：
是角色所见，还是故事中真实拍摄的影像：
允许出现的身体部位 / 反射：
允许切换视角的条件（没有则写无）：

3. 主要人物
角色 ID / 称呼：
身份、关系与当前动机：
必须稳定的可见特征：
当前连续段落的服装与状态：
参考图或文字依据（没有则写无）：

4. 主要地点
地点 ID / 名称：
入口、主要物件与行进方向的关系：
用于识别同一地点的固定特征：
当前光线、天气及环境状态：

5. 关键道具
道具 ID / 名称：
归属、初始位置和剧情作用：
再次出现时用什么特征认出它：
允许发生的变化及原因：

6. 时间与信息边界
主要事件的先后与间隔：
作者已经确定、但角色或观众尚不知道的事实：
暂时不能明确展示的内容：
允许提前出现的局部线索：
尚待决定、会影响下一步制作的问题：
```

人物、地点或道具不止一个时，复制对应条目即可。只固定真正需要重复使用的内容，不必为从未露面的角色填写完整五官，也不必为一次性背景物件建档。

## 二、设定状态：确定了什么，实现了什么

给重要条目记录两个独立状态，避免一个 `LOCKED` 同时表示作者确认和图片验收。

| 维度     | 可用状态                                 | 含义                           |
| -------- | ---------------------------------------- | ------------------------------ |
| 设定状态 | 待定 / 已确定 / 已废弃                   | 作者是否采用这项规则或事实     |
| 画面状态 | 未生成 / 待核对 / 符合 / 有偏差 / 不适用 | 指定图片是否呈现了相关可见要求 |

```text
条目 ID：
设定内容：
设定状态：
依据：作者确认 / 已采用参考图 / 其他
参考文件与版本：
已核对的图片：
画面状态与具体偏差：
处理记录链接：
```

“符合”只针对已核对的图片和特征，不代表整部作品已通过检查。无法从画面直接证明的后台事实，画面状态可写“不适用”，但它需要的视觉线索应单独核对。

**示例：**作者已确定“结尾出现的包就是开头遗失的包”。如果两张图的扣件不同，应记录为“设定已确定，画面有偏差”，再决定修正哪张图；不能直接写成“观众已认出同一只包”。

## 三、按需扩展的设定档案

以下模块只在需要时填写。相同信息只维护一处，其他文件通过 ID 或链接引用。

### A. 世界规则与整体视觉

```text
时代 / 地区 / 环境类型：
现实、幻想或科幻设定：
影响故事的社会与技术条件：

规则：
生效条件：
能力与限制：
例外及其成立原因：
角色何时知道这项规则：

画面风格与参考：
色彩、光线和清晰度原则：
目标宽高比 / 尺寸（按实际用途填写）：
可接受的模糊、噪点或曝光变化：
不可牺牲的可读信息：
```

真实手机摄影、插画、电影感画面都可以使用；不把某一种风格当成所有故事的默认要求。即使选择随手拍质感，也不能让关键线索因为模糊而失去作用。

怪物、异常现象或特殊设备可以在这里补充形态、尺度、运动方式及对环境的影响。没有这些内容的故事直接跳过。

### B. 人物档案

每个需要稳定识别或持续行动的角色复制一份。

```text
角色 ID / 姓名或称呼：
身份 / 与其他角色的关系：
动机、目标与重要行为习惯：
作者已确定的事实：
尚未确定的关系或经历：

可见识别特征：
年龄感、体型、发型及其他必要特征：
正面 / 侧面 / 背面的参考依据：
连续段落中的服装、鞋与配饰：
可以随时间改变的特征及触发条件：
不可无故改变的特征：

当前知道什么：
当前误以为什么：
当前身体和情绪状态：
```

人物性格不必被写成僵硬的动作限制，但关键选择应与动机和当时掌握的信息相容。脸、身形、穿着也不能替代人物关系的证据。

第一视角主角不露脸时，优先固定会入镜的手、袖口、鞋、随身物件等。无需为了填档案强行加入镜子或自拍。

### C. 第一视角与摄影规则

```text
视角归属：
视点高度及变化原因：
角色所见 / 手持设备拍摄 / 监控或其他影像：
身体部位可见范围：
反射、照片中本人出现的条件：
连续段落能否切换视角：
切换时怎样让观众辨认：
必要的构图、距离与清晰度限制：
```

第一视角不要求每张图都有手脚，也不自动意味着主角一直举着手机拍摄。只有采用故事内真实拍摄设定时，才需要额外解释设备、持握方式和拍摄行动。

### D. 地点、空间与机位

```text
地点 ID / 名称 / 剧情功能：
外部环境与抵达方式：
建筑、道路或房间的必要特征：
入口及出口：
主要物件的相对位置：
稳定的识别锚点：
白天 / 夜晚的光源：
可变化的环境状态及原因：
参考图或布局图：
```

| 观察位置 | 面向哪里 | 应看见的固定元素 | 被遮挡或在画外的元素 |
| -------- | -------- | ---------------- | -------------------- |
| ［位置］ | ［方向］ | ［元素］         | ［元素及原因］       |

描述左右时注明观察方向，例如“从门口向内看，桌子在左侧”。反向机位下画面左右改变，不代表空间结构改变。

重复路线可补充起点、转弯、目的地、固定地标及合理移动时间。复杂空间另附布局图；不需要地图的故事无需强行绘制。

### E. 道具与视觉身份

```text
道具 ID / 名称：
归属 / 初始位置：
剧情作用（行动工具、环境物件、线索等）：
材质、颜色、形状、尺度与磨损：
最有辨识度的特征：
参考图及版本：
允许变化的部分：
不能无故变化的部分：
```

| 出现阶段 | 所在位置 / 持有人 | 状态及变化原因 | 计划让观众识别什么 |
| -------- | ----------------- | -------------- | ------------------ |
| ［阶段］ | ［位置］          | ［状态］       | ［识别任务］       |

同款不一定是同一件。如果剧情依赖“这是之前那件物品”，应安排足够独特且可见的特征，例如相同补丁、缺口或图案组合。详细出现镜号在分镜中维护；成图是否匹配，在连续性记录中维护。

车辆可按道具建档，反复出现的建筑归入地点档案，不再重复建立两套规则。

### F. 时间线与状态变化

| 时间 / 连续段落    | 事件与地点 | 人物服装和身体状态 | 道具位置与状态 | 昼夜 / 天气及变化依据 |
| ------------------ | ---------- | ------------------ | -------------- | --------------------- |
| ［相对或绝对时间］ | ［事件］   | ［状态］           | ［状态］       | ［依据］              |

不需要精确日期时，可以写“次日”“数周后”。使用明确日期或屏幕时间时，要核对事件顺序、时间间隔和可见界面。

换装、伤势、污渍、淋湿、物品转移与环境损坏应有发生或恢复的依据。人物不必经历固定的“疲惫—受伤—恐惧”路线，只记录这个故事实际发生的变化。

### G. 屏幕、文字、照片与标识

```text
承载物 ID：手机 / 纸张 / 照片 / 招牌等
外观与版式参考：
必须准确可读的内容：
只需表现存在感的内容：
应保持模糊或被遮挡的内容及原因：
制作方式：生成 / 后期排字或合成 / 其他
```

有聊天或社交界面时补充：

```text
设备外观与屏幕开孔：
界面风格：
账号身份 / 头像：
公开昵称：
联系人备注（如与昵称不同，说明关系）：
消息顺序与必要原文：
日期、时间及“昨天”等相对时间的对应关系：
需要呈现的界面状态：
```

“没有回复”“消息发送失败”“拉黑”是不同信息。需要哪个状态，就记录它应通过什么文字或界面呈现，不能只凭空白聊天推定。

照片另记拍摄时期、照片里的人物身份、相片物理外观和识别依据。若照片必须指向某个角色，应说明观众凭什么认出；“作者知道是谁”不能替代画面的可辨识特征。标识和文字只限制未经设计的新增内容，不应一概删除剧情需要的文件或招牌。

### H. 作者真相与展示边界

| 事实 / 关系 | 作者设定状态      | 角色当前理解 | 计划给观众的可见信息 | 暂不明确展示的部分 |
| ----------- | ----------------- | ------------ | -------------------- | ------------------ |
| ［事实］    | ［已确定 / 待定］ | ［理解］     | ［线索］             | ［边界］           |

将“已经决定但暂不揭示”和“作者尚未决定”分开。需要留白时，注明留白范围；不要把缺少设定误写成刻意悬念。

限制应具体到内容和阶段，例如“允许露出照片边角，暂不显示照片中的人物身份”，而不是笼统地写“禁止出现照片”。具体镜号、信息顺序与伏笔回收放入分镜。

不预设统一保密等级、异常等级或信息释放百分比。项目确实需要等级时，自行定义，并在相关文件中保持同一套含义。

## 四、参考资料与修改记录

### 参考资料

| 条目 ID  | 参考文件 / 版本 | 用来固定什么 | 不作为依据的部分       |
| -------- | --------------- | ------------ | ---------------------- |
| ［条目］ | ［路径］        | ［特征］     | ［无关背景或已知错误］ |

参考图可能只用于固定一件衣服，不代表其中的人物、背景和光线全部被采用。不要把整张参考图的偶然细节自动升级为设定。

### 设定修改记录

| 日期 / 版本 | 修改条目 | 原设定 → 新设定 | 原因     | 受影响文件 / 图片与处理状态 |
| ----------- | -------- | --------------- | -------- | --------------------------- |
| ［日期］    | ［ID］   | ［变化］        | ［原因］ | ［影响］                    |

已确定的设定可以修改，但要显式记录，并检查关联分镜、提示词和图片。局部错误优先局部修正；若修改会破坏构图、遮挡线索或影响多个镜头，再评估重新生成。

## 五、进入分镜前检查

- [ ] 下一阶段会重复出现的人物、地点和关键道具有明确依据。
- [ ] 同一对象的固定特征与允许变化的状态已经分开。
- [ ] 视角规则与人物行动相容。
- [ ] 重要空间关系和时间顺序没有明显冲突。
- [ ] 作者真相、角色理解、计划呈现的信息没有混写。
- [ ] 待定项中，影响下一阶段制作的问题已经解决或明确暂缓范围。
- [ ] 已有图片的偏差没有被误写成已完成修正。

不必等所有背景细节填完才开始分镜；先补齐会影响下一批镜头的设定即可。

| -------------------------------------------------- | -------------------------------------------- |
| [story_idea_template.md](story_idea_template.md)   | 故事因果、动机与结局方向                     |
| 本文件                                             | 共用设定、对象身份、世界规则与允许变化的条件 |
| [storyboard_template.md](storyboard_template.md)   | 每个镜头的行动、构图任务和信息顺序           |

可以参考[《郊区网恋》的故事设定](../examples/suburban_online_romance/story_bible.md)，了解设定与成图偏差如何并存记录。该案例的视角、风格和悬念安排属于具体作品，不是所有故事都必须采用的规则。
